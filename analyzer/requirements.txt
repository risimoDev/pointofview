# torch installed separately in Dockerfile (CUDA vs CPU wheel index)

# NOTE: rfdetr (the main detector, Apache-2.0) is NOT listed here on purpose.
# It is installed by the Dockerfile after torch, under a version constraint
# that keeps the CUDA wheel from being replaced by a CPU build. Listing it in
# this file would let pip resolve torch freely and break GPU inference.

# NOTE: ultralytics (LEGACY, AGPL-3.0) is NOT listed here either — same reason
# as rfdetr, plus one more. It is installed by the Dockerfile under
# ARG WITH_ULTRALYTICS, so that `--build-arg WITH_ULTRALYTICS=0` produces an
# image with no AGPL code in it at all. That is the build the on-premise
# delivery needs, and having the switch means the licence claim is verifiable
# by inspecting the image rather than by trusting a comment.
#
# It stays installed by default only because PPE_BACKEND=yolo and
# POSE_BACKEND=yolo still work that way on прод. See docs/operations/
# PPE-TRAINING.md and POSE-RTMO.md for moving both off it.
