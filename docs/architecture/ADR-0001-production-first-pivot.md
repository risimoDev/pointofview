# ADR-0001: Производство — основной рынок, ПВЗ — дополнительный

**Статус:** действует (с 2026-07-17)
**Заменяет:** решение V-09 ([00_VISION.md](00_VISION.md), «Приоритет вертикали ПВЗ»)
**Автор решения:** владелец продукта
**Связанные документы:** [00_VISION.md](00_VISION.md), [14_FACTORY_MODULES.md](14_FACTORY_MODULES.md), [23_ENTERPRISE_INTEGRATION.md](23_ENTERPRISE_INTEGRATION.md), [18_ROADMAP.md](18_ROADMAP.md), [CAPACITY-ANALYSIS.md](../operations/CAPACITY-ANALYSIS.md)

---

## Контекст

Корпус документации проектировался с ПВЗ как основной вертикалью (решение V-09): однородность планировки, плотность рынка, готовый код детекции людей, быстрый тиражируемый доход. Производство считалось вторым рынком, к которому платформа готова архитектурно, но не продуктово.

Владелец пересмотрел приоритет: **основной рынок — производство** (малые предприятия и небольшие заводы), ПВЗ уходит в дополнительный. Первый продаваемый сценарий — контроль СИЗ. Требование к продукту — **максимально расширенный функционал** (набор узкопрофильных ИИ-моделей), а не одна функция.

## Решение

1. **Производство — основной рынок.** ПВЗ сохраняется как действующий дополнительный (текущий боевой ПВЗ продолжает работу).
2. **Первый сценарий производства — СИЗ** (каски/жилеты).
3. **Продукт — набор моделей**, а не одна функция. Ключевое техническое следствие: приоритет получают абстракция детектора и жизненный цикл плагинов (см. «Последствия»).
4. **Хостинг смешанный:** часть предприятий — на наших серверах, часть — локально (аренда/перепродажа).

## Обоснование

- Спрос на контроль ОТ/СИЗ на производстве явный и оплачиваемый; штрафы за нарушения ОТ — измеримая боль заказчика.
- On-premise-модель производства **устраняет проблему облачного трафика и архива**, которая била по экономике ПВЗ ([04_NETWORK.md](04_NETWORK.md), 16.7; [CAPACITY-ANALYSIS.md](../operations/CAPACITY-ANALYSIS.md)).
- Уход Genetec, Avigilon, Irisity с рынка РФ оставил незакрытый корпоративный сегмент.

## Последствия

### Что становится приоритетным (не было при V-09)

| Направление | Документ | Почему |
|---|---|---|
| **Абстракция детектора** | [06_AI_ENGINE.md](06_AI_ENGINE.md), 10.3 | «Много моделей» без неё = костыли в конвейере |
| **Жизненный цикл плагина** (`setup`/`teardown`) | [07_PLUGIN_SYSTEM.md](07_PLUGIN_SYSTEM.md), 7.1 | Модель грузится при включении, а не всегда — экономия VRAM |
| **Обучение модели СИЗ** | [14_FACTORY_MODULES.md](14_FACTORY_MODULES.md) | Плагин `ppe` сейчас «мёртвый»; чужой датасет не работает |
| **OPC UA** | [23_ENTERPRISE_INTEGRATION.md](23_ENTERPRISE_INTEGRATION.md), 5 | Зона у станка иначе алармит на наладчика |
| **Интеграция в чужую VMS (модель Б)** | [23_ENTERPRISE_INTEGRATION.md](23_ENTERPRISE_INTEGRATION.md), 6 | Завод не заменит свой Milestone |
| **LDAP/AD, SIEM** | [23_ENTERPRISE_INTEGRATION.md](23_ENTERPRISE_INTEGRATION.md), 3–4 | Без них не пройти ИБ-аудит завода |
| **LTS-поддержка** | [14_FACTORY_MODULES.md](14_FACTORY_MODULES.md), 12.7 | Завод эксплуатирует версию годами |
| **Железо 24 ГБ VRAM** | [CAPACITY-ANALYSIS.md](../operations/CAPACITY-ANALYSIS.md), 4 | Много моделей = много VRAM |

### Что признаётся ценой решения

- Производство — **медленнее к первой выручке**, чем ПВЗ: сначала данные + модель + интеграции, потом первый платящий клиент.
- СИЗ требует **пилотного завода с доступом к видео** — блокер, которого у ПВЗ не было.
- **Граница функциональной безопасности** ([14_FACTORY_MODULES.md](14_FACTORY_MODULES.md), F-01/F-09): СИЗ-нарушение → предупреждение и фиксация, **не** остановка оборудования. В договор.

### Что НЕ меняется

- Один код, два режима (V-01).
- Re-ID без биометрии посетителей (V-02); Face-ID только сотрудники.
- Русский UI (V-06), изоляция отказов, тенант-изоляция.
- Внедрять масштаб-инфраструктуру по триггеру, а не по графику ([20_SCALE_ARCHITECTURE.md](20_SCALE_ARCHITECTURE.md), 10).
