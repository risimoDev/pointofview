# Ёмкость и закупки — расчёт

**Обновлено:** 2026-07-17
**Назначение:** практический расчёт, что тянет железо и что покупать. Живёт вне `docs/architecture/` — это оперативный документ, а не архитектура.
**Статус данных:** оценки, не замеры. Коэффициенты помечены **[замерить]**. Полная параметрическая модель — [architecture/20_SCALE_ARCHITECTURE.md](architecture/20_SCALE_ARCHITECTURE.md), 8.

---

## 0. Контекст (решения владельца, 2026-07-17)

1. **Основной рынок — производство** (малые предприятия и небольшие заводы, немного камер, но **максимально расширенный функционал**). ПВЗ — дополнительный. Разворот приоритета зафиксирован в [architecture/ADR-0001-production-first-pivot.md](architecture/ADR-0001-production-first-pivot.md).
2. **Первый сценарий завода — контроль СИЗ** (каски/жилеты).
3. **Много узкопрофильных ИИ** — расширяем функционал набором моделей, не одной.
4. **Хостинг смешанный** — часть предприятий на наших серверах, часть локально (аренда/перепродажа).
5. **Сейчас:** 1 боевой ПВЗ на проде + тестовый тенант рядом на том же сервере.
6. **План закупки:** сервер до **500 000 ₽** под малые предприятия с полным функционалом.

---

## 1. Главный вывод

Для профиля «мало камер, много моделей» ограничитель — **не число камер и не вычисления, а VRAM**: каждая модель занимает память видеокарты постоянно, пока включена.

```
Бюджет VRAM (оценка, [замерить]):
  YOLOv8s детекция людей         ~1.0–1.5 ГБ
  Модель СИЗ (каски/жилеты)      ~1.5–2.0 ГБ
  Поза (падение, эргономика)     ~1.5–2.0 ГБ
  Огонь/дым                      ~1.0–1.5 ГБ
  Re-ID OSNet (ONNX)             ~0.5 ГБ (обычно CPU)
  OCR/штрихкод                   ~0.5–1.0 ГБ
  Локальный VLM (Qwen2.5-VL 3B Q4) ~3–4 ГБ
  ─────────────────────────────────────────
  Итого при «полном функционале»  ~10–15 ГБ
```

Следствие, определяющее закупку:

| Карта | VRAM | «Полный функционал» одновременно |
|---|---|---|
| RTX 3070 (текущая) | 8 ГБ | **Нет** — влезает 2–3 модели, не все |
| RTX 4070 Ti Super | 16 ГБ | Впритык |
| **RTX 3090 (б/у) / 4090** | **24 ГБ** | **Да, с запасом** |

**Вывод: под «малые предприятия с максимумом функций» целевая карта — 24 ГБ VRAM.** Это единственная спека, которую нельзя срезать. Малые предприятия дают мало камер (компьютер не упрётся), но много моделей (VRAM упрётся).

## 2. Что тянет текущий сервер (RTX 3070 8 ГБ, 32 ГБ RAM)

Оценки. Профиль — малое предприятие (10–40 камер).

| Ресурс | Оценка | Ограничитель |
|---|---|---|
| GPU, только люди, без батчинга (сейчас) | ~30–40 камер | Инференс по 1 кадру |
| GPU, люди, с батчингом | ~80–100 камер | ×2–3 |
| **GPU, СИЗ (детекция+классификация), с батчингом** | **~20–40 камер** | 2 стадии инференса |
| **VRAM 8 ГБ — много моделей одновременно** | **2–3 модели, не все** | **Главный лимит** |
| RAM 32 ГБ | ~80–100 камер | recorder (ffmpeg на камеру) |
| Архив на диске | **~15 ТБ/нед на 50 камер** | Диск |

**Роль текущего сервера после закупки нового:**

1. **Разработка** — file-камеры, проверка типов.
2. **Тестовый тенант рядом с боевым ПВЗ** — изоляция по `tenant_id`, file-камеры с реальных записей точки.
3. **Обучение моделей** — файнтюн YOLO для СИЗ (8 ГБ хватает на обучение одной модели).
4. **Демо-стенд** для встреч с заводами.

Под эти роли докупать вычисления не нужно — только **диск + бэкап** (см. 5).

## 3. Тестовый тенант на том же проде (без второго сервера)

Реализуемо уже сейчас, безопасно за счёт тенант-изоляции ([architecture/13_SECURITY.md](architecture/13_SECURITY.md)):

```
Боевой тенант (ПВЗ)      → rtsp_pull, реальные камеры точки
Тестовый тенант (стенд)  → source_type=file, записи с точки/завода
```

| Что | Как |
|---|---|
| Создать тестовый тенант | Отдельный `tenant_id`, свои камеры/зоны/фичи |
| Источник видео | `POST /api/v1/cameras/upload` — file-камеры (mp4 с реального объекта) |
| Изоляция | Гарантирована: `tenant_id` из JWT фильтрует всё |
| Стоимость | Доля GPU/VRAM того же сервера |
| Риск для боевого ПВЗ | Минимальный при контроле VRAM (не запускать тяжёлый VLM, пока учишь модель) |

**Ограничение:** пока VRAM 8 ГБ, тестовый тенант с полным набором моделей и боевой ПВЗ **конкурируют за память**. До нового сервера тестировать тяжёлые модели — по одной, не одновременно с обучением. Это временное неудобство, снимается картой 24 ГБ.

## 4. Новый сервер до 500 000 ₽ — конкретная спека

Профиль: малые предприятия, мало камер, **много моделей**. Цель — 24 ГБ VRAM и запас RAM/диска. Цены — ориентир РФ середины 2026, **[уточнить на момент покупки]**.

### Вариант A — новый 4090 (максимум производительности)

| Компонент | Модель (пример) | ₽ (ориентир) |
|---|---|---|
| GPU | RTX 4090 24 ГБ (новая) | 220 000–260 000 |
| CPU | Ryzen 9 7900X (12 ядер — декод RTSP + ffmpeg) | 40 000–55 000 |
| RAM | 64 ГБ DDR5 | 25 000–35 000 |
| Мат. плата | B650/X670 | 20 000–30 000 |
| NVMe система/БД | 2 ТБ | 15 000–20 000 |
| HDD архив | 2× 20 ТБ | 70 000–90 000 |
| БП | 1000 Вт (для 4090) | 15 000–20 000 |
| Корпус/охлаждение | | 15 000–25 000 |
| **Итого** | | **≈ 420 000–535 000** |

### Вариант B — б/у 3090 (та же VRAM, дешевле, больше на архив)

| Компонент | Модель (пример) | ₽ (ориентир) |
|---|---|---|
| GPU | RTX 3090 24 ГБ (б/у) | 120 000–160 000 |
| CPU | Ryzen 9 7900X | 40 000–55 000 |
| RAM | **128 ГБ** DDR5 | 50 000–65 000 |
| NVMe | 2 ТБ | 15 000–20 000 |
| HDD архив | **3× 20 ТБ** | 100 000–140 000 |
| Прочее (плата, БП 850–1000Вт, корпус) | | 55 000–85 000 |
| **Итого** | | **≈ 380 000–525 000** |

**Рекомендация: Вариант B (б/у 3090).** Обоснование: для «много моделей» решает **VRAM (24 ГБ — та же, что у 4090)**, а не пиковая скорость; сэкономленное уходит в RAM и архив, которые реально давят на малом предприятии. Риск б/у GPU — проверять при покупке (майнинг-карты). Если бюджет и надёжность важнее — Вариант A.

### Чего НЕ покупать

- Две карты, серверную платформу «на вырост», отдельную стойку — это масштаб-инфраструктура для планки, которой нет ([architecture/20_SCALE_ARCHITECTURE.md](architecture/20_SCALE_ARCHITECTURE.md), 10: внедрять по триггеру).
- Профессиональные GPU (A-серия) — переплата без выигрыша на этой задаче.

## 5. Срочно и дёшево (независимо от нового сервера)

| Покупка | ₽ | Почему срочно |
|---|---|---|
| HDD 16–20 ТБ под архив | 30 000–45 000 | 1 объект = терабайты/неделю |
| Диск/решение под бэкап | 30 000–45 000 | **Бэкапов нет — критический долг** ([architecture/02_INFRASTRUCTURE.md], I-01) |

Бэкап важнее нового сервера: сейчас отказ диска = безвозвратная потеря данных боевого ПВЗ.

## 6. Ёмкость нового сервера (24 ГБ) под малое предприятие

Оценка. Профиль: 10–40 камер, полный набор моделей.

| Показатель | Оценка [замерить] |
|---|---|
| Камер с полным функционалом (СИЗ+зоны+поза+Re-ID) на 24 ГБ, с батчингом | ~30–60 |
| Малых предприятий (по 15–25 камер) на один сервер | **1–3** |
| VLM (описания/верификация) фоново | Влезает в оставшуюся VRAM |
| Архив 20 камер × 4 Мбит/с × 7 дней | ~6 ТБ/нед → 2–3× 20 ТБ на месяц-два |

**Вывод:** один сервер 24 ГБ = 1–3 малых предприятия «под ключ» с максимумом функций. Дальше — либо локальные узлы у клиентов, либо второй сервер по триггеру.

## 7. «Много узкопрофильных ИИ» — техническое предусловие

Прежде чем подключать модели пачками, нужен фундамент, иначе каждая модель — костыль:

| Предусловие | Документ | Почему блокер |
|---|---|---|
| **Абстракция детектора** `Detector` | [architecture/06_AI_ENGINE.md](architecture/06_AI_ENGINE.md), 10.3 | Иначе `YOLO(...)` зашит в конвейер; новая модель = правка ядра |
| **Жизненный цикл плагина** `setup`/`teardown` | [architecture/07_PLUGIN_SYSTEM.md](architecture/07_PLUGIN_SYSTEM.md), 7.1 | Модель грузится при включении, а не всегда → экономия VRAM |
| **Реестр моделей** + `model_version` в событии | [architecture/06_AI_ENGINE.md](architecture/06_AI_ENGINE.md), 14.6 | Знать, какая модель что породила |
| **Батчинг** | [architecture/06_AI_ENGINE.md](architecture/06_AI_ENGINE.md), 14.1 | Много моделей на 1 GPU без него неэффективно |
| Управление VRAM (какие модели включены на тенант) | `tenant_feature` | Не держать в памяти невостребованное |

Порядок: сначала абстракция + жизненный цикл + батчинг, потом модели «как плагины». Это делает подключение новой узкопрофильной модели операцией на день, а не рефакторингом.

Кандидаты узкопрофильных моделей (подтвердить приоритет):

| Модель | Рынок | Готовность |
|---|---|---|
| СИЗ (каски/жилеты) | Завод | Учить на данных пилота |
| Поза → падение человека | Завод, ПВЗ | YOLOv8-pose, готовая |
| Огонь/дым | Завод, склад | Готовые модели, проверять |
| Разлив/утечка | Завод | Сегментация, сложнее |
| Штрихкод посылки | ПВЗ | pyzbar, простая |
| Погрузчики | Склад | Учить |
| Оставленный предмет | Общий | Есть подходы |

## 8. Дорожная карта закупок (по триггерам, не датам)

| Триггер | Действие | ₽ |
|---|---|---|
| Сейчас | HDD архив + бэкап | 60–90 тыс. |
| Первый пилот-завод согласился дать видео | Ничего (учим на текущем 3070) | 0 |
| Готова модель СИЗ + первый платящий клиент | **Сервер 24 ГБ (Вариант B)** | ~400–500 тыс. |
| 2–3 предприятия на новом сервере, VRAM/канал упёрлись | Локальные узлы у клиентов (аренда/перепродажа) | По проекту, часто capex клиента |
| Облачное предприятие с многими камерами | Оставить архив локально у клиента, к нам — субпоток+события | Аплинк |

## 9. Что померить, чтобы цифры стали точными

Все «~» выше закрываются мониторингом ([architecture/12_MONITORING.md](architecture/12_MONITORING.md)):

| Метрика | Даёт |
|---|---|
| `viziai_inference_duration_seconds` | Реальная ёмкость GPU |
| Утилизация CPU по ядрам | Упирается ли декод RTSP |
| VRAM по моделям | Сколько моделей влезет |
| ГБ архива в сутки на камеру | Точный размер диска |
| Кадров/с на камеру | Проверка `frame_skip` |

До замеров планирование ёмкости — гипотеза. Поэтому **батчинг + минимальный мониторинг** — первая инженерная работа (см. стартовый промпт сессии).
