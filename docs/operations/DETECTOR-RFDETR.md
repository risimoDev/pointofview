# Переключение детектора на RF-DETR

**Зачем:** уйти с ultralytics (AGPL-3.0) на RF-DETR (Apache-2.0). Это главный лицензионный блокер: пока он не снят, нельзя поставлять on-premise, подавать в Реестр отечественного ПО и давать в договоре заверение об отсутствии прав третьих лиц. Обоснование — [../commercial/01_LICENSE_REMEDIATION.md](../commercial/01_LICENSE_REMEDIATION.md), решение 1.

**Что уже сделано в коде:** адаптер `analyzer/detect/rfdetr.py` за существующей абстракцией `make_detector`, установка пакета в `analyzer/Dockerfile`, переменные окружения в compose. Переключение — одна переменная.

> Берутся только размеры Nano, Small, Medium, Large — они под Apache-2.0. XL и 2XL идут под отдельной лицензией PML 1.0 и в продукт не допускаются; в адаптере они недоступны намеренно.

---

## 1. Две ловушки, которые уже закрыты в коде

Обе тихие, обе сломали бы систему без единой ошибки в логе. Знать о них нужно, чтобы понимать, что проверять.

**Индексация классов.** У RF-DETR `person` имеет идентификатор **1** (91-классная разметка COCO), а конвейер работает в 80-классной, где `person` равен 0. Прямая подстановка дала бы «людей нет ни на одной камере» при полностью исправной системе. Адаптер строит соответствие **по именам классов** при старте, пишет найденный идентификатор в лог и падает при старте, если класса `person` нет вовсе.

**Разрешение.** RF-DETR принимает только значения, кратные 56. Текущее `yolo_imgsz=640` не подходит (640 / 56 = 11,43). Адаптер округляет к ближайшему допустимому и предупреждает в логе, но на проде лучше задать значение явно.

**Третья ловушка — в сборке, а не в работе.** Пакет `rfdetr` объявляет собственное требование к torch, и обычная установка разрешает его через PyPI, подменяя CUDA-сборку на CPU-сборку. Инференс после этого уезжает на процессор молча. В Dockerfile установка идёт с ограничением на уже установленную версию torch и с дополнительным индексом CUDA, а после неё стоит проверка: если torch всё-таки подменили, **сборка падает**.

## 2. Настройка

В `infra/.env.prod`:

```
DETECTOR_KIND=rfdetr
DETECTOR_IMGSZ=672
RFDETR_SIZE=small
```

Про значения:

- `DETECTOR_IMGSZ=672` — ближайшее к прежним 640 кратное 56 в большую сторону. Если нужна скорость, берите 616; если камеры дают мелких людей в кадре — 728.
- `RFDETR_SIZE=small` — по точности заметно выше прежней `yolov8s` при сопоставимой скорости. `nano` — если упрётесь в видеопамять, `medium` — если её хватает и нужна точность.
- `RFDETR_WEIGHTS` оставить пустым: возьмутся предобученные веса, запечённые в образ при сборке.

Пересборка и запуск:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --build analyzer
```

## 3. Проверка. Все четыре пункта обязательны

**Torch остался с поддержкой CUDA** — если тут `False`, детекция работает на процессоре и всё остальное бессмысленно:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod exec -T analyzer python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

**Детектор поднялся и классы сопоставлены** — в логе должна быть строка вида `rfdetr: coco-small, resolution 672, person native id=1 -> canonical 0, 80 of 91 classes mapped`:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod logs --tail 200 analyzer | grep -E "rfdetr|AGPL"
```

Предупреждения про AGPL быть уже **не должно** — оно печатается только для `detector_kind=yolo`.

**Люди действительно находятся.** Это главная проверка, и её нельзя заменить чтением логов: пройдите перед камерой и убедитесь, что событие появилось в журнале, а счётчик людей отреагировал. Ночью на пустой точке проверять бесполезно.

**Видеопамяти хватает** — RF-DETR делит карту с Ollama:

```bash
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
```

## 4. За чем наблюдать первые сутки

RF-DETR — трансформерная архитектура, она ведёт себя иначе, чем YOLO, и различия проявятся именно на ваших камерах:

| Что смотреть | Где | Признак проблемы |
|---|---|---|
| Число событий за ночь | `/events` | Резкий рост «Нарушение зоны» с пустым кадром — поднять `yolo_conf` |
| Счётчик посетителей за день | `/analytics` | Кратное расхождение с реальностью |
| Мелкие и удалённые люди | живое видео | Пропуски на дальнем плане — увеличить `DETECTOR_IMGSZ` до 728 |
| Время распознавания | карточка метрик в `/admin/features` | Заметный рост против прежнего |

---

## 5. Откат

Одна переменная и перезапуск, пересборка не нужна — путь `yolo` остаётся в образе:

```
DETECTOR_KIND=yolo
DETECTOR_IMGSZ=
```

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --no-deps analyzer
```

Откат не закрывает лицензионный вопрос: с `detector_kind=yolo` поставка on-premise остаётся невозможной, и в логе снова появится предупреждение.

---

## 6. Что остаётся на ultralytics после этого шага

Переключение детектора **не удаляет** ultralytics из образа: на нём ещё держатся плагин позы (`analyzer/plugins/pose.py`) и плагин СИЗ (`analyzer/plugins/ppe.py`). Полное удаление зависимости — последний шаг после их миграции на RTMO и на собственную модель СИЗ.
