# Перевод детекции падения на RTMO

**Зачем:** снять вторую зависимость от ultralytics (AGPL-3.0). После этого шага остаётся только плагин СИЗ, и зависимость можно удалять из образа целиком. Обоснование — [../commercial/01_LICENSE_REMEDIATION.md](../commercial/01_LICENSE_REMEDIATION.md), решение 2.

**Что такое RTMO:** одностадийная модель оценки позы из проекта MMPose (Apache-2.0). Одностадийная значит, что она находит людей и их суставы за один проход и не требует отдельного детектора в видеопамяти. Запускается через `rtmlib` — тонкую обёртку на чистом ONNX Runtime, без mmcv и без второго torch.

---

## 1. Что изменилось в коде

По образцу детектора выделена абстракция `analyzer/pose/`: `base.py` (протокол и нейтральный `PoseDetection`), `yolo.py` (прежний бэкенд), `rtmo.py` (новый). Плагин `plugins/pose.py` больше не знает, какая модель под ним.

**Одно содержательное изменение в эвристике.** Признак «человек на полу широкий в кадре» раньше считался по рамке от модели позы. RTMO рамку не отдаёт вовсе, а построенная по суставам — заметно уже, чем рамка детектора, и порог `min_aspect_down` начал бы означать другое. Теперь пропорция берётся **из рамки трека**, которая приходит от основного детектора и одинакова при любом бэкенде. Логика проверена: стоящий и наклонившийся не считаются упавшими, лежащий считается.

---

## 2. Модель

Файл ONNX не скачивается автоматически. Это сознательно: установка на изолированном объекте должна работать, а модель неизвестного происхождения — ровно то, из-за чего затеян лицензионный аудит.

Возьмите ONNX-экспорт RTMO из официальных источников проекта: список моделей в README библиотеки `rtmlib` либо экспорты RTMO на Hugging Face. Нужен вариант на 17 суставов COCO. Начинать стоит с самого лёгкого — `rtmo-s`.

Проверьте лицензию конкретного файла и запишите её происхождение в `THIRD_PARTY_LICENSES.md` — это то, о чём спросит служба безопасности заказчика.

```bash
scp rtmo.onnx viziai-server:${DATA_ROOT}/models/
```

---

## 3. Включение

В `infra/.env.prod`:

```
POSE_BACKEND=rtmo
RTMO_MODEL=/models/rtmo.onnx
```

Пересборка нужна один раз — в образ добавляется `rtmlib`:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --build analyzer
```

В логе сборки должно быть `rtmlib imports ok`. Если этой строки нет — сборка упала, и на прод ничего не уехало.

Затем включите функцию «Падение человека» в `/admin/features` (модель грузится в видеопамять при включении и выгружается при выключении).

---

## 4. Проверка

Бэкенд поднялся:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod logs --tail 100 analyzer | grep -E "pose:|AGPL"
```

Ожидается `pose: rtmo backend, model /models/rtmo.onnx, input 640x640, device cuda`. Предупреждения про AGPL от модуля позы быть не должно.

Если файла нет, плагин сообщит об ошибке в `/admin/features` с указанием пути — молчаливого отката на ultralytics нет намеренно.

Видеопамять: RTMO одностадийный, поэтому расход должен быть не больше прежнего, а скорее меньше.

```bash
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
```

**Проверка по существу — имитация падения.** Лечь на пол в поле зрения камеры и не вставать дольше `min_down_seconds` (по умолчанию 5 секунд). Должно прийти критическое событие `fall_detected`. Без этой проверки считать модуль работающим нельзя: всё остальное подтверждает только загрузку модели.

---

## 5. Подстройка

Пороги те же, что были, и живут в конфигурации функции в `/admin/features`:

| Параметр | Смысл | Куда двигать |
|---|---|---|
| `fall_angle_deg` (65) | Угол оси тела от вертикали | Ниже — чувствительнее, больше ложных на наклонах |
| `min_aspect_down` (0.85) | Ширина рамки трека к высоте | Ниже, если реальные падения не подтверждаются |
| `min_down_seconds` (5) | Сколько лежать | Ниже — быстрее реакция, больше ложных на приседаниях |
| `min_checks_down` (3) | Проверок подряд | Защита от мерцания |
| `min_confidence` (0.4) | У RTMO — средняя уверенность по суставам | Поднять, если ловятся обрывки скелетов |

Обратите внимание: у RTMO `min_confidence` считается как средняя уверенность по суставам, а не как уверенность детектора. Шкала другая, и значение, подходившее для yolov8-pose, может потребовать правки.

---

## 6. Откат

```
POSE_BACKEND=yolo
```

и перезапуск анализатора. Пересборка не нужна, старый бэкенд остаётся в образе. Откат не снимает лицензионный вопрос.
