# Переход сквозной идентификации на DINOv2

**Зачем:** заменить эмбеддер OSNet, веса которого не имеют пригодной лицензии и обучены на исследовательских датасетах, на DINOv2 (Apache-2.0). Обоснование — [../commercial/01_LICENSE_REMEDIATION.md](../commercial/01_LICENSE_REMEDIATION.md), решение 3.
**Заменяет:** [REID-OSNET.md](REID-OSNET.md) — тот документ оставлен только для отката.

> DINOv3 использовать нельзя: у него собственная ограничительная лицензия с регистрацией пользователя. Нужен именно DINOv2.

---

## 1. Экспорт модели (на dev-ПК)

```bash
pip install torch transformers onnx
python scripts/export_reid_dinov2.py --out dinov2_vits14.onnx
```

Размер `small` даёт вектор 384 и файл около 90 МБ — этого достаточно для сопоставления по одежде и силуэту. `base` точнее, но вдвое тяжелее и на CPU считается заметно дольше; брать только если `small` не устроит по качеству.

## 2. Установка на сервере

```bash
scp dinov2_vits14.onnx viziai-server:${DATA_ROOT}/models/
```

В `infra/.env.prod`:

```
REID_ONNX=/models/dinov2_vits14.onnx
REID_ONNX_KIND=dinov2
```

Пересобрать анализатор:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --build analyzer
```

## 3. Проверка, что подхватилось

В логах анализатора должна быть строка вида:

```
reid embedder: ONNX /models/dinov2_vits14.onnx kind=dinov2 (dim 384, вход 224x224) — пороги 0.82/0.86
```

Если вместо неё `reid embedder: HSV histograms` — файл не найден или не загрузился, причина в строке выше. Молчаливого отката к гистограммам без записи в лог не бывает: это сделано специально, потому что снаружи он неотличим от работающей нейросети, а пороги у них различаются вдвое.

Тип эмбеддера и рекомендуемые пороги также видны в карточке «Сквозная идентификация» в `/admin/features`.

## 4. Обязательные действия после переключения

Порядок важен.

1. **Сброс обучения.** `/admin/features` → карточка «Сквозная идентификация» → «Сброс обучения», область `all`. Эмбеддинги старого формата несопоставимы с новыми: без сброса галерея и карточки сотрудников превращаются в мусор, который никогда ни с чем не совпадёт.
2. **Пороги.** Выставить `match_threshold = 0.82`, `staff_threshold = 0.86`. Это отправная точка, а не истина: смотрите пункт 5.
3. **Заново отметить сотрудников** на странице «Люди»: имя, затем 2–3 фото анфас, затем дать человеку походить перед камерами, чтобы набрались эталоны одежды.

## 5. Подстройка порогов по месту

Пороги 0.82/0.86 подобраны по типичному поведению признаков DINOv2 и **обязаны быть проверены на объекте**. Признаки, по которым понятно, куда двигать:

| Симптом | Что происходит | Действие |
|---|---|---|
| Число посетителей за день кратно больше реального | Порог совпадения слишком высок, один человек дробится на многих | Понижать `match_threshold` шагами по 0.02 |
| Разные люди склеиваются в одну личность, счётчик занижен | Порог слишком низок | Повышать шагами по 0.02 |
| Сотрудник опознаётся как посетитель | Высок `staff_threshold` | Понижать, но не ниже `match_threshold` |
| Посторонний принимается за сотрудника | Низок `staff_threshold` | Повышать |

Ориентир для проверки — тот же, что и в прошлый раз: ночная смена с известным числом людей. Ошибка «2 курьера ночью = 44 посетителя» была именно порогом.

## 6. Откат

Если DINOv2 покажет себя хуже на конкретном объекте, откат — это две строки в `.env.prod` (`REID_ONNX_KIND=osnet` и путь к старому файлу) плюс сброс обучения и пороги 0.70/0.75. Но помните, что OSNet — временный режим: поставлять его заказчику нельзя, он оставлен только на период миграции.
