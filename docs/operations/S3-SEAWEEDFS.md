# Переход объектного хранилища с MinIO на SeaweedFS

**Зачем две причины, и вторая важнее первой.** MinIO распространяется под AGPL-3.0, что закрывает поставку on-premise. Но, кроме этого, **репозиторий сообщества MinIO заархивирован в феврале 2026** — обновлений безопасности нет. Это вопрос уже не лицензии, а эксплуатации, и он всплывёт на первом же аудите информационной безопасности заказчика.

SeaweedFS — Apache-2.0, живой проект, S3-совместимый шлюз встроен. Клиент в API не меняется вообще: он говорит по S3, меняется только адрес.

**Обоснование выбора:** [../commercial/01_LICENSE_REMEDIATION.md](../commercial/01_LICENSE_REMEDIATION.md), решение 5.

---

## Принцип: без простоя и с возможностью вернуться

SeaweedFS добавлен в `docker-compose.prod.yml` **рядом** с MinIO, на отдельном порту. Данные копируются при работающем MinIO, переключение — одна переменная. Пока не переключено, прод продолжает работать на MinIO, и откат ничего не стоит.

Это осознанно другой подход, чем при переходе на Valkey, где подмена образа положила сервис на полчаса.

---

## 1. Поднять SeaweedFS

Ничего переключать не нужно, он просто начнёт работать на порту 9002.

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d seaweedfs
```

Проверить, что поднялся:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod ps seaweedfs
```

Учётные данные берутся из `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` — те же, что у MinIO, чтобы не менять их в API при переключении. Файл идентичностей пишется при старте контейнера из переменных окружения и в репозиторий не попадает.

## 2. Скопировать объекты

```bash
./scripts/s3-migrate.sh
```

Скрипт копирует бакеты `clips` и `snapshots` через rclone и сверяет число объектов с обеих сторон. Он идемпотентный: повторный запуск переносит только недостающее.

Важно понимать, что лежит в `snapshots`, кроме кадров событий: фотографии карточек людей (`reid/`) и **набор данных для дообучения** (`fp/`). Терять его нельзя — это накопленная разметка ложных срабатываний.

Если счётчики разошлись, скрипт откажется признать перенос успешным и вернёт ненулевой код. Запустите ещё раз.

## 3. Дозалить свежее прямо перед переключением

Между копированием и переключением система продолжает писать в MinIO. Прогоните ещё раз — перенесётся только разница, это займёт секунды:

```bash
./scripts/s3-migrate.sh
```

## 4. Переключение

В `infra/.env.prod` поменять внутренний адрес:

```
MINIO_ENDPOINT=http://seaweedfs:8333
```

`MINIO_PUBLIC_ENDPOINT` **не трогать** — публичное имя `s3.<домен>` остаётся прежним, presigned-ссылки подписываются им.

Дальше нужно отдать SeaweedFS хостовый порт 9000, потому что именно на него ходит nginx с VPS. Остановите MinIO и поднимите SeaweedFS на 9000:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod stop minio
```

Добавьте в `.env.prod` строку `SEAWEEDFS_PORT=9000` и пересоздайте:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --force-recreate seaweedfs
```

Затем перезапустите потребителей, чтобы они взяли новый адрес:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d --no-deps --force-recreate api worker-clips worker-alerts worker-ai
```

## 5. Проверка

Порядок от простого к сложному — так сразу видно, на каком уровне сломалось.

Хранилище видно из API:

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod logs --tail 50 api | grep -iE "minio|s3|error"
```

В `/admin` на странице диагностики состояние MinIO должно быть «ок» (проверка ходит по S3 API, имя в интерфейсе осталось прежним).

**Главная проверка — presigned-ссылки.** Это единственное место, где SeaweedFS может повести себя иначе, чем MinIO: браузер и Telegram открывают объекты по подписанной ссылке, и подпись должна сойтись на публичном хосте.

1. Откройте `/events`, найдите событие с кадром — картинка должна отобразиться.
2. Откройте `/admin/training` — кадры набора данных должны отображаться.
3. Откройте карточку человека на странице «Люди» — фото должно отображаться.
4. Вызовите тестовое оповещение с кадром — фото должно прийти в Telegram.

Если картинки не открываются, а в остальном всё работает — проблема именно в подписи, и это повод откатиться и разбираться, а не «оставить как есть».

## 6. Откат

Вернуть в `.env.prod`:

```
MINIO_ENDPOINT=http://minio:9000
```

убрать `SEAWEEDFS_PORT=9000`, поднять MinIO обратно и пересоздать потребителей. Данные в `${DATA_ROOT}/minio` всё это время не менялись — MinIO был только источником чтения.

## 7. После того как проработает несколько дней

Удалить сервис `minio` из `docker-compose.prod.yml` и переименовать переменные `MINIO_*` в `S3_*` — сейчас они сохранены намеренно, чтобы переключение не требовало правок в коде API.

Каталог `${DATA_ROOT}/minio` не удалять, пока не будет свежей резервной копии нового хранилища.
